Google Search Console API Testing Checklist

Published July 3, 2026 · By SmartX QA Team · 5 min read

Google Search Console provides four main API endpoints for programmatic access to search data. Each endpoint has unique testing requirements that go beyond simple success/failure checks. This checklist covers the critical test scenarios for each API, including edge cases that are easy to miss.

API 1: Search Analytics (searchAnalytics.query)

The Search Analytics API is the most complex GSC endpoint. It accepts numerous parameters including date ranges, dimensions, filters, and row limits. A thorough test plan must cover parameter combinations, not just individual parameters.

Dimension Tests

Dimensions control how data is grouped. The API supports: query, page, country, device, searchAppearance, and date. Each dimension changes the response structure — the keys array in each row matches the requested dimensions.

DimensionVerify
querykeys[0] = search query string
pagekeys[0] = full URL
devicekeys[0] = MOBILE, DESKTOP, or TABLET
countrykeys[0] = 3-letter country code (ISO 3166-1 alpha-3)
datekeys[0] = YYYY-MM-DD
query,page (multi)keys[0] = query, keys[1] = page URL

Filter Tests

Filters narrow results without changing the grouping. Each filter specifies a dimension, operator (contains, equals, notContains, notEquals, includingRegex, excludingRegex), and expression.

// Filter by page URL containing "/blog/"
{ "dimension": "page", "operator": "contains", "expression": "/blog/" }

// Filter by country equals USA
{ "dimension": "country", "operator": "equals", "expression": "USA" }

// Regex filter for queries starting with "how to"
{ "dimension": "query", "operator": "includingRegex", "expression": "^how to" }

API 2: URL Inspection (urlInspection.index.inspect)

The URL Inspection API provides indexing status for a specific URL. Key response fields to verify include verdict (PASS, FAIL, NEUTRAL), coverageState, robotsTxtState, indexingState, lastCrawlTime, and canonical URL comparison.

API 3: Sitemaps (sitemaps.list / sitemaps.submit)

The Sitemaps API has two operations: listing submitted sitemaps and submitting new ones. The list operation returns metadata about each sitemap including error counts, submission dates, and content type breakdowns (web, image, video, news).

Key Assertions for sitemap.list

For each sitemap entry, verify: path (full URL), lastSubmitted (ISO timestamp), lastDownloaded (when Google last fetched it), isPending (boolean), isSitemapsIndex (boolean), errors (count), warnings (count), and contents array with type/submitted/indexed counts.

API 4: Sites (sites.list)

The simplest API — returns all Search Console properties the authenticated user has access to. Each entry includes siteUrl and permissionLevel (siteOwner, siteFullUser, siteRestrictedUser, siteUnverifiedUser).

Test with accounts that have multiple properties at different permission levels. Verify that the permission level matches what's configured in GSC web UI. Test with an account that has no properties — should return an empty array, not an error.

Cross-Cutting Concerns

Regardless of which API you're testing, several concerns apply across all endpoints. Data freshness: GSC data has a 2-3 day delay for finalized data. Using data_state: "all" returns fresher but potentially incomplete data. Property format: both URL-prefix (https://example.com/) and domain (sc-domain:example.com) formats must be tested. Rate limiting: the API enforces quotas per project — tests must handle 429 responses gracefully.
